- Arcbit v3.1已正式开发完成并结项；产品版本为`v3.1`，修改日期为`260901`。“层叠消融”的软件接入、全量构建、内部固件烧录和实板验收全部通过，当前无遗留待验证事项。

## 2. 新游戏接入流程

1. 明确玩法、模式数量、结算条件、主记录指标、长期数据结构和快照内容；所有缓冲区使用静态定长设计。
2. 在`GameId`中分配10，并保持ID永久稳定。为游戏建立浅层`Game`派生类；复杂纯规则可拆成独立rules文件。
3. 完整实现`Game`接口：运行、输入、局部绘制、模式选择、MENU文字、持久数据、快照、HOME缩略图、入口页、结算和记录摘要。完整签名以`game.hpp`为准。
4. 在`app.cpp`静态创建对象并加入`games[]`。通用APP流程应自动接管页面、玩家、存档、记录和关机，不增加游戏ID专用结算分支。
5. 将固定中文加入`ui_text.cpp`；游戏只发送`UiSoundId`语义事件，随机数只使用`Rng_get_range_int()`。
6. 长期数据自行维护版本和长度，最大508 B；快照包含游戏自己的magic、版本和有效性检查，最大1536 B。结构大小使用`static_assert`固定。
7. 实现`record_summary()`和`format_record_variant()`；高分型记录设置数值越大越优，最快型记录设置`lower_is_better`。
8. 验证新局、操作、结算、记录更新、快照恢复、玩家隔离、HOME/MENU/PAUSE、主题、局部刷新和关机保存，最后执行Keil全量构建与实板验收。

## 3. 稳定平台契约

- `app.cpp`以单一`PageId`和显式`switch`管理页面；游戏静态注册，不使用堆、RTOS、异常、RTTI或完整帧缓冲。
- 主循环每轮只捕获一次按键状态和边沿。游戏接收方向键及Y/X/L/R/A/B，HOME/MENU/PAUSE由APP统一处理。
- HOME与游戏入口组成游戏环；游戏提供透明缩略图和入口内容，APP负责公共背景、Header、焦点和三个HOME按钮。
- 首次进入、页面返回、主题切换和唤醒可整页绘制；游戏运行和普通控件应只刷新变化区域。
- 固定中文由构建前脚本从UTF-8生成GBK安全源码；公开文字绘制接口和LCD驱动接口不得改变。
- APP统一处理玩家、跨玩家记录、音量/音效密度、低电提醒、自动变暗、存储错误和安全关机，游戏不得建立平行实现。
- LCD默认12.5 MHz；只有确有带宽需要并恢复公共页面频率时才使用已验证的25 MHz，50 MHz只用于诊断。

## 4. 玩家与存储

| 层 | 当前格式与容量 |
| --- | --- |
| `PlayerDirectory` | 最多6名玩家 |
| `AppProfile` | v5，每玩家32 B通用设置 |
| `GameCatalog` | v2，10款游戏目录摘要，256 B |
| `GameDataStore` | v1，10个条目，每游戏508 B负载 |
| 游戏快照 | 每游戏独立A/B双槽，最大1536 B |

- 当前资料格式简称`P5/C2`。既有格式保持冻结；新增游戏只增加自己的长期数据和快照版本。
- 每名玩家使用128 KB固定区域。长期数据和快照均检查记录头、提交标记和CRC；仅一槽有效时底层静默补齐另一槽。
- `GameDataStore`整体不可用才进入存储错误；单游戏版本、长度或内容无效时只恢复该游戏默认值。
- 快照只在PAUSE、HOME和关机等检查点保存；有快照时更改模式前必须确认删除。
- Flash地址和GameId槽位公式只查Flash文档及JSON清单，不在游戏代码中另建地址表。
